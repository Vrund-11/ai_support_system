# SupportPilot Official Knowledge Base Corpus

## Section 1: Authentication and Account Security

SupportPilot supports Single Sign-On (SSO) via SAML 2.0 and OpenID Connect (OIDC). Supported identity providers include Google Workspace, Okta, Microsoft Azure Active Directory, and PingIdentity.
To configure SSO, the account Owner must upload the identity provider metadata XML document and specify the ACS URL and Entity ID found under Organization Settings > Security.
Multi-Factor Authentication (MFA) is strictly required for all users with Lead or Owner roles. MFA can be configured using TOTP authenticator apps such as Google Authenticator, 1Password, or Authy.
Password policies require a minimum length of 12 characters, including at least one uppercase letter, one lowercase letter, one number, and one symbol. Passwords expire every 90 days.
If an account is locked due to 5 consecutive failed login attempts, an automated unlock link is sent to the registered email address with a 15-minute validity window.

## Section 2: Billing, Subscriptions, and Invoices

SupportPilot offers three distinct subscription plans: Starter, Growth, and Enterprise.
The Starter plan costs $29 per seat per month billed monthly, or $24 per seat per month billed annually. It includes up to 5 agent seats and standard email ticketing.
The Growth plan costs $79 per seat per month and includes up to 25 seats, live chat widgets, and basic AI assistant routing.
The Enterprise plan costs $149 per seat per month with custom seat limits, dedicated account management, custom SLA automation, and high-volume vector search.
Invoices are generated on the first calendar day of every billing cycle. Invoices are emailed to the primary billing contact and downloadable as PDF files under Billing > History.
All subscription fees are non-refundable after 14 calendar days from the initial purchase or renewal date.
Refund requests submitted within 14 days of subscription initiation are processed back to the original credit card within 5 to 7 business days.

## Section 3: REST API and Webhooks

SupportPilot exposes a RESTful API versioned at `/api/v1` for programmatic access to tickets, messages, and customer profiles.
All API requests must include a valid Bearer API key in the `Authorization` header: `Authorization: Bearer <api_key>`.
API keys can be generated by account Admins under Settings > API Keys. Each key can be scoped to read-only or read-write permissions.
Rate limits for the standard API are enforced at 120 requests per minute per IP address and 1,000 requests per minute per tenant.
When a rate limit is exceeded, the server responds with HTTP status code 429 Too Many Requests and an `X-RateLimit-Reset` timestamp header.
Webhooks can be registered to listen for lifecycle events including `ticket.created`, `ticket.updated`, `ticket.assigned`, and `message.received`.
Webhook deliveries include an HMAC-SHA256 signature in the `X-SupportPilot-Signature` header computed using the tenant webhook signing secret.

## Section 4: Live Chat Widget and Handoff

The SupportPilot live chat widget can be embedded on any website using a single asynchronous `<script>` tag.
The widget opens an encrypted WebSocket connection over Socket.IO to the SupportPilot Gateway.
When a customer sends a message, it is first evaluated by the AI assistant using hybrid retrieval and the tenant knowledge base.
If customer confidence is below the tenant threshold (default 0.55), the conversation is automatically transitioned to `WAITING_AGENT` status.
Customers can request a human agent at any time by typing phrases like "speak to a human" or "talk to an agent", triggering instant escalation.
Sensitive topics matching the tenant blocklist (such as legal threats, active fraud, or data breaches) bypass the AI and immediately escalate with High priority.
During escalation, the complete conversation transcript is compiled and converted into a tracked support ticket in the agent inbox.

## Section 5: Team Management and RBAC Matrix

SupportPilot enforces Role-Based Access Control (RBAC) across four roles: AGENT, LEAD, ADMIN, and OWNER.
Agents can view assigned tickets, respond to customers, add internal notes, and toggle ticket statuses between Open, On Hold, and Resolved.
Leads can view all tenant tickets, reassign tickets across team members, and view team performance analytics.
Admins can manage team member invitations, modify SLA business hours, and configure third-party integrations like Slack and Jira.
Owners possess full billing authority, can delete the organization, and manage API keys and SSO SAML settings.
Agents cannot delete tickets or modify tenant brand configuration.
